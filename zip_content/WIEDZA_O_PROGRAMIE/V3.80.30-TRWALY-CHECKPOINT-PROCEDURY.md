# V3.80.30 — trwały checkpoint procedury

Przed rozpoczęciem przebiegu, mapy i każdej komendy RCON program zapisuje `procedure_run` w globalnym zapisie. Jeżeli checkpoint nie jest trwały, komenda nie trafia do kolejki. Wynik aktualizuje etap, w tym osobne `doexit_sent`, `waiting_for_return` i `map_verified`.

Po przerwaniu procesu zapisany przebieg blokuje automatyczne RCON po ponownym uruchomieniu. Program nie zgaduje, czy uzbrojona komenda została wysłana, i nie wysyła jej ponownie. Operator po ręcznej kontroli usuwa blokadę osobnym kliknięciem; procedura nie startuje w tym samym kliknięciu.

To jest odzyskiwanie fail-closed, nie automatyczne wznowienie. Realna walidacja po zabiciu procesu podczas RCON na Windows/ASA pozostaje niewykonana.
