# V3.83 „JEDEN PLUGIN KONFIGURACJI”

Dwa pluginy — **„Importer starych konfiguracji”** (80) i **„Backup / Przywracanie”**
(81) — są teraz jednym: **„Konfiguracje — import, backup, przywracanie”**
(`PLUGINY/80_konfiguracje.py`, wersja 2.0.0).

## CO WIDAĆ
- Jeden przycisk na górnym pasku: **IMPORT / BACKUP**.
- Jeden panel z dwiema zakładkami: **IMPORT ZE STAREGO REFRESHERA** oraz
  **BACKUP I PRZYWRACANIE**.
- Jedna karta w Managerze Pluginów, jeden przełącznik ON/OFF.
- Działanie importu i backupu bez zmian (ten sam kod, te same testy).

## ZAPISANE WYBORY ON/OFF
Przy pierwszym starcie plugin jednorazowo przejmuje wybory starych pluginów:
- którykolwiek ze starych był ON → nowy jest ON,
- oba były OFF → nowy jest OFF,
- brak zapisanych wyborów → ON (jak dawny importer).
Wybór zapisuje się pod nową nazwą `konfiguracje`; od tej chwili decyduje tylko on.

## STARE PLIKI W FOLDERZE PLUGINY
Kto rozpakuje nową wersję NA starą, zostanie ze starymi plikami
`80_importer_starych_konfigow.py` i `81_backup_restore.py`. Nowy plugin deklaruje
`zastepuje = ("importer_starych_konfigow", "backup_restore")`, a host pluginów
(`asaonly/pluginy.py`) takich pluginów nie ładuje — w dzienniku pojawia się wpis,
że stary plik można usunąć. Mechanizm jest ogólny: każdy przyszły plugin może
zastąpić wcześniejsze tym samym atrybutem.

## NAPRAWA: PRZYWRÓCONA KONFIGURACJA ZNIKAŁA
Po przywróceniu backupu program pracował dalej ze STARYM stanem w pamięci.
Zwykłe zamknięcie (bez niezapisanych zmian program zapisuje wszystko) albo
jakikolwiek zapis w trakcie tworzył nowsze pliki ze starym stanem, a program
przy starcie czyta najnowsze — przywrócona konfiguracja przepadała po cichu.

Teraz po udanym przywróceniu program pokazuje komunikat i **zamyka się BEZ
zapisywania** (`App._zamknij_teraz()`, ta sama ścieżka co „Zamknij i nic nie
zapisuj”). Wystarczy uruchomić go ponownie. Przywracanie jest też zablokowane
w trakcie procedury restartu i czuwania nad mapą.
