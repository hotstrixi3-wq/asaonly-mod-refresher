# V3.86 — AKTUALIZACJA SERWERA PRZEZ WŁASNY CACHE

Plugin 88 „Aktualizacja serwera (SteamCMD)” w wersji 2.0.0. Prośba usera
(26.09.2026): updater ma działać poprawnie i nie czekać 20 minut po wykryciu
nowego buildu. Decyzje usera: własny cache refreshera; wykrywanie przez
api.steamcmd.net co minutę, zapasowo SteamCMD.

### Dlaczego „Access Denied”
- SteamCMD aktualizuje instalację różnicowo: potrzebuje manifestu buildu, który
  na niej leży. Bierze go z własnego `depotcache`, a gdy go tam nie ma — prosi
  Steam.
- Mapy instalował SteamCMD **managera** (jego content_log: 25.09 00:42–00:48
  commity do genesis_wp, ragnarok_wp, extinction_wp) i tylko on miał
  `depotcache\2430931_8699400601246504390.manifest`. W depotcache refreshera był
  wyłącznie nowy manifest 6068136383897274900.
- Steam wydał loginowi anonimowemu nowy manifest, a starego odmówił. Dlaczego
  odmawia starego — **nie wiem** (Valve tego nie opisuje; ten sam błąd dla tej
  samej aplikacji: github.com/Acekorneya/Ark-Survival-Ascended-Server/issues/104,
  bez wyjaśnienia). Fakt z logów: SteamCMD managera w całej historii (9.09–25.09)
  pobierał tylko manifesty docelowe i ani razu nie dostał „Access Denied”.
- Włączone „Weryfikuj pliki” (`validate`) nic nie zmieniało — błąd pada przed
  weryfikacją, w fazie „Reconfiguring”.

## JAK ROBI TO MANAGER (ASADedicatedManager 3.8.2.3, kod przejrzany lokalnie)

Okno „Update Settings” (klasy UpdateService, UpdateSettings, CacheUpdateManager):
1. co „Check Interval” (lista: 20 min, 30 min, 1 hour … 24 hours — **mniej niż
   20 min się nie da**), gdy włączone „Enable automatic update checking”:
   manifest z `api.asadedicatedmanager.com/v1/info/2430930` porównywany
   z appmanifest każdego serwera,
2. nieaktualny serwer → aktualizacja cache `CacheUpdatePath` (u usera
   `C:\ARKservers\ASA UPDATES`) **jego** SteamCMD — delta działa, bo to ten sam
   SteamCMD, który cache instalował; przed startem SteamCMD manager zabija
   **każdy** `steamcmd.exe` na komputerze (`taskkill /F /IM steamcmd.exe /T`),
3. pole „Update all servers … Only update cache !” (w oknie managera z symbolami
   pól wyboru przed obiema częściami) zaznaczone: ostrzeżenia RCON
   („Server restart warning delay”, wiadomość z `{minutes}`), zatrzymanie serwerów
   („Restart offset between servers”), kopia **wszystkich** plików cache (bez
   `steamapps` i `steamcmd`) do każdego serwera, kopia appmanifest, start serwerów
   co „waiting times between server restarts”; niezaznaczone: tylko cache.
Błąd pobierania cache = przerwanie przed zatrzymaniem serwerów — dobrze.
Słabsze strony: min. 20 min opóźnienia, ~12 GB zapisu na serwer przy każdej
aktualizacji, brak wycofania przy błędzie kopiowania, zabijanie cudzych SteamCMD.

## JAK JEST TERAZ (V3.86)

1. **Wykrywanie** — co 60 s `https://api.steamcmd.net/v1/info/2430930`
   (nieoficjalna, otwarta usługa — nie Valve; bez klucza; wg jej strony dane są
   „zwykle w kilka sekund” po zmianie na Steamie; limitów nie podaje — HTTP 429
   = czekanie tyle, ile każe). Gdy API nie odpowiada: SteamCMD co 5 min; gdy
   działa: SteamCMD raz na godzinę kontrolnie. Pierwsze sprawdzenie 30 s po starcie.
2. **Cache** — `<folder serwerów>\ASA UPDATES REFRESHER` (folder nad pierwszą
   mapą; inny ustawisz w panelu). Aktualizuje go **zawsze ten sam** SteamCMD
   refreshera (`+force_install_dir <cache> +login anonymous +app_info_update 1
   +app_update 2430930 [validate]`), więc manifest cache jest zawsze u niego.
   Serwery w tym czasie działają, manager nie jest wstrzymywany. Pierwsze
   pobranie ~12 GB (sprawdzenie wolnego miejsca: rozmiar z API + 2 GB).
   Błąd → **żaden restart**; w dzienniku linie z `content_log.txt` (ostatnia
   sesja SteamCMD) i następna próba po 5, 15, 30 min. Gdyby Steam odmówił
   manifestu buildu leżącego w cache (np. usunięty depotcache) — drugi raz bez
   appmanifest cache (skan i dociągnięcie), serwery nietknięte.
3. **Plan** (przy działającym serwerze, `asaonly/synchronizacja.py`): pliki
   cache vs pliki mapy — kopiować, gdy brak, inny rozmiar, albo inny czas
   i inna treść; ta sama treść i inny czas (np. po kopii managera) = tylko
   wyrównanie czasu. Nigdy: `steamapps`, `steamcmd`, `ShooterGame\Saved`.
   Nic do kopiowania, a starszy tylko appmanifest = sam appmanifest, bez restartu.
4. **Kolejka** — mapa GOTOWA ze starszym buildem niż cache: zwykła kolejka
   (gracze `ListPlayers`, ogłoszenia z harmonogramu, pusta = od razu, jeden start
   naraz). `przed_doexit`: aktualny plan? cache gotowy (StateFlags 4)? miejsce na
   dysku mapy (bajty planu + 2 GB)? → wstrzymanie managera → DoExit.
5. **Podmiana** (po wyłączeniu serwera): każdy plik → `<plik>.refresher-tmp`
   (kopia z zachowaniem czasu) → stary do `<mapa>\.refresher-kopia\…` → nowy na
   miejsce; appmanifest **ostatni** (jego build = dowód kompletności). Dziennik
   `<mapa>\.refresher-kopia\dziennik.json` zapisywany przed każdą podmianą.
   Błąd = wycofanie (stare pliki wracają, nowe dodane są usuwane) i serwer wstaje
   na dotychczasowym buildzie. Awaria refreshera w trakcie = strażnik
   (`python -m asaonly.zamrazanie`) najpierw cofa z dziennika, potem wznawia
   managera; to samo robi następny start refreshera. Po sukcesie kopia zapasowa
   jest usuwana, manager wznawiany i sam podnosi serwer.
6. **Mapa bez działającego serwera** (OFFLINE/CRASH albo 30 min nie GOTOWA, bez
   procesu serwera): to samo bez DoExit i bez kolejki.
7. **Jeden restart, nie dwa** — gdy Steam ma nowszy build niż cache, mapy czekają,
   aż cache go dogoni; w trakcie rundy restartów (czekające zlecenia pluginu,
   podmiana w toku) cache nie jest ruszany.
8. **Jeden updater** — z `%LOCALAPPDATA%\ASADedicatedManager\*\*\user.config`
   plugin czyta tylko `AutoCheckUpdates`, `AutoApplyUpdates`, `UpdateMethod`,
   `CacheUpdatePath`, `UpdateCheckIntervalMinutes` (bez haseł i tokenów).
   `AutoCheckUpdates = True` („Enable automatic update checking”) → plugin nic nie
   pobiera i nie podmienia, w dzienniku powód, na wskaźniku „STOP”. Nie ma pliku →
   ostrzeżenie „nie wiem”, plugin działa. Cache refreshera nie może być cache
   managera ani katalogiem (albo podkatalogiem) mapy.
9. **Limity** — najwyżej 3 nieudane podmiany na build (co najmniej 30 min
   odstępu), potem tylko AKTUALIZUJ TERAZ. Pobieranie do cache nie ma limitu prób
   (nie dotyka serwerów), ma przerwy 5/15/30 min.
