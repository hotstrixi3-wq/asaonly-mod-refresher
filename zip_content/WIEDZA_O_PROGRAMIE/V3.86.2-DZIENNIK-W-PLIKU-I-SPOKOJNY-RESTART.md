  tekstu i zrzutu ekranu. Napis przy starcie mówił „zapis też w asa_debug.log”, ale

- **Planowy restart wyglądał jak awaria.** Po DoExit z kolejki: „PAD: process gone with
  no crash trace (died quietly)” (Genesis 1 14:36:42, Ragnarok 14:39:26), „Status
  change … OFFLINE” na czerwono i czerwone „[CPU] … PID=none … No process” przy każdej
  fazie startu (Genesis 1: 14:36:32, 14:36:42, 14:37:38, 14:37:43).
- **Enter w oknie refreshera.** Kliknięcie w okno cmd włączyło zaznaczanie (tryb szybkiej
  edycji) i Windows wstrzymał wypisywanie do czasu Enter. Od 3.85.2 czekał tylko wątek
  konsoli (program działał dalej — godziny zdarzeń na zrzucie idą bez przerwy).
- **CPU po READY — już tak było.** Plugin CPU zmienia priorytet/affinity dopiero przy
  GOTOWY i ≥30 s od startu procesu (Extinction: GOTOWY 14:36:14 → affinity 14:36:16;
  Genesis 1: 14:38:58 → 14:39:00); wcześniej tylko odczyt („LOADING_MODS — no
  intervention”). Priorytet High w trakcie ładowania ustawia **manager**: w jego logu
  przy każdym starcie „Set CPU Priority to: High” ok. 25 s po starcie procesu (Genesis:
  start 14:37:37, High 14:38:02; wpis „Affinity is disabled (checkbox unchecked)”).
  Kod managera 3.8.2.3: lista priorytetu ma Idle, BelowNormal, Normal, AboveNormal, High,
  RealTime — pozycji „nie ustawiaj” nie ma. Żeby CPU było ruszane dopiero po GOTOWY:
  w managerze ustawić priorytet tych serwerów na **Normal**; refresher po GOTOWY ustawi
  cel z panelu CPU (u usera: High + affinity).

## CO ZMIENIONO
1. **Dziennik w pliku** — `asaonly/dziennik_plik.py` (`PisarzPliku`, osobny wątek z
   kolejką, jak `asaonly/konsola.py`). `App._oproznij_dziennik()` wysyła tę samą paczkę
   linii do konsoli (z kolorami ANSI) i do pliku (bez kolorów). Plik:
   `WIEDZA_O_PROGRAMIE\dziennik-zdarzen.txt`; wiersz `=== <data> · start programu
   <wersja> ===` na starcie i `=== <data> ===` przy zmianie dnia (linie mają tylko
   godzinę); rotacja jak `dziennik-modow.txt`: 5 MB → `dziennik-zdarzen.01.txt`, najwyżej
   5 kopii. Błąd zapisu nie zatrzymuje programu — raz trafia do `asa_debug.log`.
   Przy zamknięciu programu zaległe linie (też z zamykania pluginów) trafiają do konsoli
   i pliku. Plik jest w ZIP-ie diagnostyki (plugin 82, z zamaskowanymi sekretami),
   w `.gitignore`; testy piszą do katalogu tymczasowego (`ASAONLY_EVENT_LOG_DIR`).
   Poprawiony napis `console_hint`. Wersja programu w jednej stałej `WERSJA_PROGRAMU`.
2. **Spokojny restart** — `ProcedureMixin.mapa_w_restarcie(nazwa)`: mapa po udanym
   DoExit z kolejki (czuwanie powrotu), jeszcze nie z powrotem GOTOWA.
   - monitor procesów: zniknięcie procesu bez śladu crasha w tym czasie →
     „[mapa] Serwer zamknięty po DoExit (planowy restart) — czekam, aż wróci.”;
     ślad crasha w logu nadal daje „PAD: … po śladzie crasha”;
   - `log_status(…, nazwa=)`: OFFLINE takiej mapy na żółto, nie na czerwono;
   - widok map dla pluginów (`TabSnapshot.restart`), plugin CPU 1.3.2: stan
     „Restart po DoExit — CPU dopiero po READY” w panelu, a w dzienniku [CPU] tylko przy
     GOTOWY (fazy startu, OFFLINE, CRASH — tylko panel). GOTOWA mapa bez procesu nadal
     daje czerwone ostrzeżenie; zmiany CPU i ich potwierdzenie — bez zmian.
   Przy okazji: druga linia wpisu [CPU] zaczynała się od znaku U+21B3, który na zrzucie z okna cmd
   usera wyświetla się jako prostokąt (skaner gangu też go zgłaszał); teraz „→” — ten
   znak to samo okno pokazuje poprawnie („ListPlayers → empty”).
3. **Okno konsoli bez zatrzymań** — `asaonly/konsola.py`: `wylacz_szybka_edycje()` przy
   starcie (Windows, tylko gdy jest konsola): `SetConsoleMode` wejścia konsoli bez
   `ENABLE_QUICK_EDIT_MODE` (0x0040), z `ENABLE_EXTENDED_FLAGS` (0x0080) — tak każe
   dokumentacja Microsoft; `przywroc_tryb()` przy zamknięciu. W dzienniku wpis, jak
   kopiować tekst: menu okna → Edytuj → Zaznacz albo plik dziennika.

## CACHE MANAGERA (pytanie usera)
„Jak raz ustawić cache w managerze, to wyłączenie tego jest chyba niemożliwe” — tak:
w kodzie managera 3.8.2.3 są dwie metody aktualizacji (SteamCMD i CDN), każda z własną
ścieżką cache, bez opcji „bez cache”. Nie trzeba go wyłączać: przy odznaczonym „Enable
automatic update checking” okresowe sprawdzanie managera nie działa (UpdateCheckTimer),
a cache jest używany tylko przy aktualizacji uruchomionej w managerze ręcznie. Refresher
pilnuje tylko, żeby jego cache nie był cache managera.
- `C:\ARKservers\ASA UPDATES` — cache managera (user.config: `CacheUpdatePath`,
  `UpdateMethod` = SteamCMD), build 25489097; potrzebny tylko do ręcznej aktualizacji
  w managerze.
- `C:\ARKservers\update cache` — starszy cache SteamCMD managera (build 24922743,
  25.08.2026; same paki ok. 12,15 GB), nie ma go w ustawieniach managera — można usunąć
  ręcznie.
